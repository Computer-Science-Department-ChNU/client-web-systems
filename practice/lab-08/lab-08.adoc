= Лабораторна робота №8

*Тема:* React Fundamentals: компоненти, JSX, props, стан, події та списки.

*Мета:* ознайомитися з базовими принципами розробки застосунків на React.
Навчитися створювати компоненти, передавати дані через props, керувати локальним станом за допомогою `useState`, обробляти події, відображати списки та використовувати умовний рендеринг.

У цій та наступних лабораторних роботах розробляється один спільний навчальний застосунок **Study Planner**.
Кожна наступна лабораторна розширює попередню та додає нові можливості React.

== Вимоги до звіту

. Лабораторна робота виконується в окремому GitHub репозиторії студента або у виділеній гілці проєкту, відповідно до вимог викладача.
. Застосунок повинен бути реалізований з використанням React та TypeScript.
. Використовувати React 19.x та Node.js 22.22 або новішу версію.
. Для створення UI необхідно використовувати JSX/TSX.
. Застосунок повинен бути поділений на компоненти відповідно до їхньої відповідальності.
. Дотримуватися єдиного стилю коду та використовувати ESLint.
. Для стилізації використати один із підходів: SCSS із дотриманням BEM, Bootstrap або Tailwind CSS. Обраний підхід використовувати послідовно в межах роботи.
. Не використовувати `alert` для повідомлення користувачу.
. Код повинен бути розміщений в особистому GitHub репозиторії студента.
. Дотримуватися Conventional Commits під час виконання роботи.

== Практична частина

=== Стилізація та BEM

Для стилізації обрати один із трьох підходів:

. **SCSS + BEM** — власні стилі з класами за схемою Block__Element--Modifier;
. **Bootstrap** — готові utility та component класи;
. **Tailwind CSS** — utility-first класи.

Не потрібно поєднувати всі три підходи одночасно.

Якщо обрано **SCSS + BEM**:

* стилі організувати за компонентами або логічними блоками;
* назви класів повинні відповідати BEM;
* не прив'язувати стилі до глибокої структури DOM;
* уникати глобальних стилів, які випадково впливають на інші компоненти.

=== Постановка задачі

Створити клієнтський застосунок **Study Planner** — простий планувальник навчальних завдань.

На першому етапі застосунок працює лише з даними, що зберігаються в пам'яті React.
Після перезавантаження сторінки дані можуть скидатися.
Збереження у `localStorage`, Context API, `useReducer`, REST API, Router та інші можливості будуть додані в наступних лабораторних роботах.

Очікуваний основний сценарій:

. користувач бачить список навчальних завдань;
. може додати нове завдання;
. може позначити завдання як виконане;
. може видалити завдання;
. бачить загальну кількість завдань та кількість виконаних;
. може переглядати лише всі або лише невиконані/виконані завдання.

=== 1. Створення React-проєкту

. Створити новий проєкт Vite + React + TypeScript.
. Переконатися, що проєкт використовує React 19.x та Node.js 22.22 або новішу версію.
. Налаштувати запуск застосунку через npm.
. Переконатися, що TypeScript та ESLint працюють без помилок.
. Ознайомитися зі структурою стартового проєкту.
. Видалити демонстраційний код, який не потрібний для лабораторної роботи.

Проєкт має бути створений на основі Vite + React.

=== 2. Модель навчального завдання

Описати тип даних `Task` за допомогою TypeScript.

Завдання повинно містити щонайменше:

* унікальний `id`;
* `title` — назву;
* `description` — короткий опис;
* `completed` — ознаку виконання;
* `priority` — пріоритет;
* `category` — категорію.

Допустимі значення пріоритету: `low`, `medium`, `high`.

Приклад даних:

[source,typescript]
----
const initialTasks: Task[] = [
  {
    id: 1,
    title: 'React Components',
    description: 'Опрацювати базові принципи компонентів React',
    completed: false,
    priority: 'high',
    category: 'React',
  },
  {
    id: 2,
    title: 'TypeScript Exercises',
    description: 'Виконати практичні вправи',
    completed: true,
    priority: 'medium',
    category: 'TypeScript',
  },
];
----

=== 3. Компоненти застосунку

Розділити застосунок щонайменше на такі компоненти:

* `App`;
* `Header`;
* `TaskForm`;
* `TaskList`;
* `TaskItem`;
* `TaskFilters`;
* `TaskStats`.

Компоненти повинні взаємодіяти через props та callback-функції.

Не слід зберігати всю логіку в одному файлі `App.tsx`.

=== 4. Відображення списку завдань

Створити компонент `TaskList`, який отримує список завдань через props та відображає його за допомогою `map`.

Для кожного елемента необхідно використовувати стабільний `key`.

Компонент `TaskItem` повинен відображати:

* назву;
* опис;
* категорію;
* пріоритет;
* стан виконання;
* кнопки керування.

Для виконаного завдання передбачити помітну візуальну відмінність.

=== 5. Додавання завдання

У компоненті `TaskForm` реалізувати форму з полями:

* Назва;
* Опис;
* Категорія;
* Пріоритет.

При натисканні кнопки «Додати» нове завдання повинно з'явитися у списку.

Після успішного додавання форма повинна очиститися.

Поле назви повинно бути обов'язковим.
Порожнє завдання додавати не можна.

Валідація у цій лабораторній може бути простою та виконуватися без сторонніх бібліотек.

=== 6. Зміна стану завдання

Для кожного завдання реалізувати можливість:

. позначити завдання виконаним;
. повернути завдання у стан «не виконано»;
. видалити завдання.

Оновлення масиву завдань повинно виконуватися незмінно (immutable update), без прямої зміни існуючого масиву або об'єкта.

=== 7. Фільтрація завдань

У компоненті `TaskFilters` реалізувати три режими:

* Всі;
* Виконані;
* Не виконані.

При зміні фільтра список на екрані повинен змінюватися без зміни вихідного масиву завдань.

Активний фільтр повинен бути візуально позначений.

=== 8. Статистика

Створити компонент `TaskStats`, який показує:

* загальну кількість завдань;
* кількість виконаних;
* кількість невиконаних.

Статистика повинна автоматично оновлюватися після додавання, видалення або зміни стану завдання.

Для отримання кількості використайте поточний масив завдань та звичайні JavaScript-операції над масивами, наприклад `filter()` або `length`.
На цьому етапі не потрібно використовувати окремий state для кожного лічильника.

=== 9. Умовний рендеринг

Реалізувати повідомлення для порожнього списку.

Наприклад:

----
Завдань поки немає.
Додайте перше навчальне завдання.
----

Для порожнього результату поточного фільтра виводити окреме повідомлення, наприклад:

----
За цим фільтром завдань немає.
----

Кнопка видалення повинна бути доступна лише там, де це логічно потрібно, а виконане завдання повинно мати інший візуальний стан.

=== 10. Оформлення

Створити простий, акуратний інтерфейс.

Рекомендована структура:

[source]
----
Study Planner
├── Header
├── TaskForm
├── TaskStats
├── TaskFilters
└── TaskList
    ├── TaskItem
    ├── TaskItem
    └── ...
----

Не потрібно відтворювати складний дизайн.
Головна мета цієї лабораторної — продемонструвати роботу React-компонентів та стану.

=== 11. Додаткові завдання

За бажанням реалізувати один або декілька додаткових пунктів:

. Пошук завдань за назвою.
. Сортування за пріоритетом.
. Лічильник кількості завдань безпосередньо у кнопках фільтра.
. Кнопку «Очистити виконані».
. Вибір кольору або іконки для категорії.
. Темну тему на рівні UI.

Додаткові можливості не повинні замінювати виконання основних вимог.

src/

├── App.tsx

Структура може бути змінена студентом, якщо збережено логічний поділ відповідальності компонентів.

На цьому етапі не потрібно будувати складну архітектуру. Основна увага — зрозумілим компонентам, props, state та подіям.

Не потрібно використовувати feature-first, FSD, Repository Pattern, глобальні state managers або інші складні архітектурні підходи.

== Демонстрація на захисті

За час захисту необхідно продемонструвати:

. додавання нового завдання;
. перемикання завдання між станами «виконано» / «не виконано»;
. роботу одного з фільтрів;
. компонентну структуру та у коді показати використання props і `useState`.

Не потрібно демонструвати всі додаткові завдання.
