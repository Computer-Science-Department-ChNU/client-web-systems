Організація State

Де зберігати state? — чотири типи

Правило: стан має жити як можна нижче в дереві компонентів. Піднімаймо його вгору лише тоді, коли цього потребують кілька компонентів.

Правила визначення місця для state

  • Локальний стан — якщо дані використовуються лише одним компонентом (form input, toggle, modal open/close) → useState у цьому компоненті.
  • Спільний стан (shared) — якщо дані потрібні кільком компонентам → підняти до найближчого спільного предка (Lifting State Up).
  • Спільне далеко розташоване дане — якщо воно потрібне багатьом частинам дерева (auth, theme, locale) → useContext або стейт-менеджер (Zustand, Redux), коли це справді спрощує код.
  • Серверний стан — дані, які приходять з API і мають власний життєвий цикл (cache, refetch, loading, synchronization) → TanStack Query, SWR, RTK Query. Для простого локального запиту звичайний state теж можливий.

Інструменти управління станом

useState — коли використовувати

  • 1-2 незалежні значення
  • прості типи (string, number, boolean)
  • нескладна логіка оновлення
  • стан локальний (один компонент)

Приклади:

useReducer — складний state

// useState — простий стан
function Counter() {
  const [count, setCount] = useState(0);
  const reset = () => setCount(0);
  const inc = () => setCount(c => c + 1);
  const dec = () => setCount(c => c - 1);
}
// useReducer — складний стан
function reducer(state, action) {
  switch(action.type) {
    case "inc": return {count: state.count+1};
    case "dec": return {count: state.count-1};
    case "reset": return {count: 0};
  }}

  • 1-2 незалежних значень
  • прості типи (string, number, bool)
  • нескладна логіка оновлення

toggle, input value, counter

useReducer коли:

  • кілька пов'язаних значень
  • наступний стан залежить від попереднього
  • складна логіка оновлення
  • потрібна тестованість логіки

forms, multi-step wizards, cart

useReducer — приклад

// 1. Reducer function (pure)
type State = { count: number; step: number };
type Action =
  | { type: "inc" }
  | { type: "dec" }
  | { type: "setStep"; step: number }
  | { type: "reset" };

function reducer(state: State, action: Action) {
  switch (action.type) {
    case "inc": return { ...state, count: state.count + state.step };
    case "dec": return { ...state, count: state.count - state.step };
    case "setStep": return { ...state, step: action.step };
    case "reset": return { count: 0, step: 1 };
  }
}
// 2. Використання в компоненті
function Counter() {
  const [state, dispatch] =
    useReducer(reducer,
      { count: 0, step: 1 });

  return (
    <div>
      <p>{state.count} (step: {state.step})</p>
      <button
        onClick={() => dispatch({ type: "inc" })}>+</button>
      <button
        onClick={() => dispatch({ type: "dec" })}>-</button>
      <button
        onClick={() => dispatch({ type: "reset" })}>Reset</button>
    </div>
  );
}

Переваги: логіка винесена з компонента, редюсер — чиста функція (легко тестувати), actions типізовані.

Ключові принципи state

  • State — immutable. Ніколи не змінюй стан напряму: state.x = 5 ✗. Завжди створюй новий об'єкт: setState({...state, x: 5}) ✓.
  • React оновлює state не миттєво. React може об'єднувати кілька оновлень в один render. Не очікуй, що одразу після setState змінна вже має нове значення. Для нового значення на основі попереднього використовуй функціональну форму: setCount(prev => prev + 1).
  • Не дублюй state. Якщо дані можна обчислити з props або іншого state — не зберігай їх окремо (derived state).
  • Стан живе в найближчому спільному предку. Чим вищий стан — тим більше компонентів перерендеряться.

Derived state — обчислюйте, не зберігайте

// Погано — дубльований state
function ProductList(props) {
  const [items, setItems] = useState([]);
  const [visibleCount, setVisibleCount] = useState(0);

  useEffect(() => {
    setVisibleCount(items.filter(i => i.active).length);
  }, [items]);
}
// Добре — обчислення під час рендеру
function ProductList(props) {
  const [items, setItems] = useState([]);

  const visibleItems = items.filter(
    i => i.active
  );
  // або useMemo для дорогих обчислень
  const sorted = useMemo(
    () => [...items].sort(...), [items]
  );
}

Якщо значення можна отримати з існуючого state/props — обчислюй його під час рендеру. useMemo — лише для дорогих обчислень.

Обмін даними та Props Drilling

Lifting State Up — підняття стану

Lifting State Up — як це працює

Якщо два дочірніх компоненти потребують одні й ті ж дані → стан піднімається до їх спільного батька.

Алгоритм:

  1. Визначити, які компоненти використовують спільні дані.
  2. Знайти їх найближчого спільного предка в дереві.
  3. Перемістити туди useState.
  4. Передати дані вниз через props, а callbacks — для оновлення.

Це базовий механізм React для передачі спільного стану між компонентами. Аналог у Vue — provide/inject або спільний reactive-об'єкт.

Props Drilling — проблема

Props drilling — коли дані передаються через кілька рівнів компонентів, які самі ці дані не використовують, а лише передають їх далі.

Props Drilling — чому це погано

  • Порушення інкапсуляції — проміжні компоненти знають про дані, які їм не потрібні.
  • Складність рефакторингу — зміна форми даних торкається всіх компонентів на шляху.
  • Зайвий код і зв'язки — проміжні компоненти мусять приймати й передавати props, а зміни в цьому ланцюжку можуть вимагати повторного render.
  • Важко читати — незрозуміло, звідки дані приходить і куди йдуть.

Рішення: Context API, композиція компонентів, стейт-менеджери (Zustand, Redux), або винесення логіки в Custom Hooks.

Context API — передавання даних через дерево

const TaskContext =

<TaskContext.Provider value={{

  {children}
</TaskContext.Provider>

Context дає спільні дані піддереву; компонент читає їх через useContext().

Context API — приклад у React 19

// 1. Створити Context
import { createContext, useContext, useState, type ReactNode } from "react";

type User = { name: string; role: string };
const UserContext = createContext<User | null>(null);

// 2. Provider — у React 19 context-об'єкт можна використовувати без .Provider
function App() {
  const [user, setUser] = useState<User>({ name: "Anna", role: "admin" });
  return (
    <UserContext value={user}>
      <Layout />
    </UserContext>
  );
}

// 3. Consumer — читає значення в будь-якому місці всередині Provider
function UserProfile() {
  const user = useContext(UserContext);
  if (!user) return <p>Not logged in</p>;
  return <p>Hello, {user.name} ({user.role})</p>;
}

Аналог у Vue — provide / inject. У React 19 context-об'єкт можна використовувати безпосередньо як provider: <UserContext value={user}>. .Provider залишається сумісним варіантом для старішого коду.

Context — обережно з продуктивністю

Важливо: коли значення Context змінюється, React оновлює компоненти, які читають цей Context. Тому Context не варто перетворювати на «одне сховище для всього».

Рішення:

  • Розділяти контексти (UserContext, ThemeContext окремо);
  • Для складного object/function value useMemo може зменшити зайві оновлення споживачів, коли самі дані не змінилися;
  • Для часто змінного стану — Zustand (підписка на конкретне поле);
  • Не зберігати в Context дані, що змінюються кожен рендер.

Context не означає «глобальний state для всього». Його зручно використовувати, коли одне значення потрібно багатьом компонентам у піддереві: theme, current user, locale, налаштування тощо. Якщо props достатньо — краще залишити props.

Композиція компонентів — альтернатива

function Layout({ sidebar, children }) {
  return (
    <>
      <aside>{sidebar}</aside>
      <main>{children}</main>
    </>
  );
}

// Layout не знає, які дані всередині.

Композиція дозволяє передавати готовий UI замість зайвого props drilling.

Коли Context недостатньо

Context + useReducer — вбудований інструмент React для спільного стану. Підходить для низькочастотних даних (theme, auth, locale).

Коли Context стає вузьким місцем (часті оновлення, складні залежності, серверний стан) — використовують зовнішні стейт-менеджери:

  • Client state: Zustand, Jotai, Redux Toolkit
  • Server state: TanStack Query, SWR, RTK Query

Детально ці інструменти розглянемо в Лекції 15: State Management та Production React.

Правило: починай з useState + props/Lifting State Up. Додавай Context, коли одне й те саме значення потрібно багатьом компонентам у піддереві. Зовнішній стейт-менеджер — коли він реально спрощує роботу зі спільним станом.

Side Effects та useEffect

Що таке side effects?

Чиста функція — функція, яка для однакових вхідних даних завжди повертає однаковий результат, без побічних ефектів.

Компоненти React мають бути чистими функціями від props та state: UI = f(props, state).

Side effect (побічний ефект) — будь-що, що виходить за межі чистої функції:

  • HTTP-запити (fetch, axios);
  • Підписки (WebSocket, EventSource, addEventListener);
  • Таймери (setTimeout, setInterval);
  • Пряма маніпуляція DOM;
  • Запис у localStorage / sessionStorage;
  • Логування, аналітика.

useEffect потрібен, коли після оновлення інтерфейсу треба зробити щось поза React або синхронізуватися з чимось поза React: підключитися до сервера, встановити підписку, змінити browser API, запустити timer або синхронізувати сторонню бібліотеку. Простими словами: render показує UI, а Effect допомагає узгодити UI із зовнішнім світом.

useEffect — коли запускається Effect

Після render React оновлює інтерфейс, потім запускає Effect. Якщо залежності змінилися, спочатку виконується cleanup попереднього Effect, а потім setup нового.

Подія чи Effect?

Подія (event handler)

Код запускається через конкретну дію користувача:

  • клік по кнопці;
  • введення в input;
  • submit форми.

onClick → змінити state, відправити форму, перейти на сторінку.

Effect

Код запускається тому, що компонент відобразився або його дані змінилися:

  • підключитися до WebSocket;
  • синхронізувати <video> з state;
  • підписатися на resize.

useEffect → синхронізація із системою поза React.

useEffect — як це працює

useEffect — приклади

// 1. Запит після першого render
useEffect(() => {
  let ignore = false;
  fetch("/api/user")
    .then(r => r.json())
    .then(data => {
      if (!ignore) setUser(data);
    });
  return () => { ignore = true; };
}, []);

// 2. Підписка на зовнішню подію
useEffect(() => {
  const handler = () => setWidth(window.innerWidth);
  window.addEventListener("resize", handler);
  return () => window.removeEventListener("resize", handler);
}, []);
// 3. React to prop/state change
useEffect(() => {
  document.title = `User: ${user.name}`;
}, [user.name]); // тільки при зміні name

// 4. Timer with cleanup
useEffect(() => {
  const id = setInterval(() => {
    setTime(new Date());
  }, 1000);
  return () => clearInterval(id);
}, []);

// 5. Запит, коли змінюється query
useEffect(() => {
  fetchResults(query).then(setResults);
}, [query]); // dep!

useEffect — часті помилки

// 1. Безкінечний цикл
useEffect(() => {
  setCount(count + 1);
}); // без deps!
// setCount → re-render → effect → setCount...

// 3. Немає cleanup
useEffect(() => {
  window.addEventListener("resize", handler);
  // forgot removeEventListener
}, []);
// memory leak при unmount
// 2. Пропущений dep
useEffect(() => {
  fetch(`/api?q=${query}`);
}, []); // query ✕
// stale closure — query залишиться старим

// 4. Effect для обчислень
useEffect(() => {
  setFiltered(items.filter(...));
}, [items]);
// краще: const filtered = items.filter(...)
// useMemo — лише як оптимізація для дорогих обчислень

Коли НЕ потрібен useEffect

// Обчислення з props/state — без Effect
const filtered = items.filter(i => i.active);
// useMemo — лише як оптимізація, якщо обчислення справді дороге

// Не копіюй prop у state через Effect
// Якщо треба скинути локальний state при зміні id,
// часто достатньо змінити key компонента:
<Form key={userId} userId={userId} />
// Реакція на user event
useEffect(() => {
  if (submitted) submitForm(data);
}, [submitted]);
// const handleSubmit = () => submitForm(data);

useEffect потрібен для:

  • підключення до сервера або іншого API
  • підписки на події, WebSocket та інші зовнішні джерела
  • робота з browser API / DOM, коли JSX недостатньо
  • timers, analytics, logging та інші зовнішні інтеграції

React 19.2 — useEffectEvent

import { useEffect, useEffectEvent } from "react";

function ChatRoom({ roomId, theme }) {
  const onConnected = useEffectEvent(() => {
    showNotification("Connected!", theme);
  });

  useEffect(() => {
    const connection = createConnection(roomId);
    connection.on("connected", onConnected);
    connection.connect();

    return () => connection.disconnect();
  }, [roomId]);
}

Effect Event — спеціальна функція для логіки, яку викликає Effect, але яка повинна бачити актуальні props/state без перезапуску самого Effect.

  • бачить актуальні значення під час виклику;
  • не додається в dependency array Effect;
  • викликається тільки з Effect або іншого Effect Event.

Не використовуй useEffectEvent, щоб просто сховати залежність від Effect. Спочатку правильно вкажи dependencies.

Це React 19.2+ API для складніших сценаріїв Effect; у звичайних випадках достатньо коректно вказати всі залежності та cleanup.

useEffect vs useLayoutEffect

useEffect

  • Запускається після commit; зазвичай — після paint;
  • Зазвичай дозволяє браузеру спершу намалювати оновлений UI;
  • Більшість side effects;
  • fetch, subscriptions, timers.

useLayoutEffect

  • Виконується після DOM-мутацій, але до paint (синхронно);
  • Блокує браузер;
  • Для вимірювання DOM (getBoundingClientRect);
  • Для попередження мигання (flicker).

Правило: завжди починай з useEffect. Переходь на useLayoutEffect лише якщо бачиш візуальне мигання (flicker) при оновленні DOM.

Правила Hook-ів

  • Викликай Hooks лише на top-level — не всередині циклів, умов, вкладених функцій.
  • Викликай Hooks лише з React-функцій — компонентів або інших Custom Hooks.
  • Порядок має значення — React покладається на порядок виклику для ототожнення стану.
  • React Compiler може автоматично оптимізувати багато випадків мемоізації; не додавай useCallback та useMemo «про всяк випадок».
  • eslint-plugin-react-hooks — встановлюй для автоматичної перевірки правил та deps.

Custom Hooks

Custom Hooks — перевикористання логіки

// БЕЗ Custom Hook (дублікація)
function SearchA() {
  const [q, setQ] = useState("");
  useEffect(() => { setTimeout... });
  // debounce logic duplicated...
}
// та ж логіка в SearchB, SearchC...
// З Custom Hook (1 місце)
function useDebounce(value, delay) {
  const [d, setD] = useState(value);
  useEffect(() => { ... }, [value]);
  return d;
}
// використовується скрізь

Використання:

function SearchBar() {
  const debouncedQuery = useDebounce(query, 300);
  // debounce logic is reusable
  return <input value={query} onChange={...} />;
}

Custom Hook — правила

Custom Hook — це JavaScript-функція, ім'я якої починається з use, і яка може викликати інші Hook-и.

Конвенції:

  • Ім'я обов'язково починається з use (useFetch, useToggle, useLocalStorage);
  • Повертає значення або масив (як useState, useReducer) або об'єкт;
  • Може приймати аргументи (URL, ключ, початкове значення);
  • Всередині може викликати useState, useEffect, інші hooks;
  • Custom Hook відповідає за логіку та стан, а не за побудову власного UI-компонента.

Аналог у Vue — Composables (useMousePosition, useFetch).

Custom Hook — useToggle

// hooks/useToggle.ts
import { useState } from "react";

export function useToggle(initial: boolean = false) {
  const [value, setValue] = useState(initial);

  const toggle = () => setValue(prev => !prev);
  const setTrue = () => setValue(true);
  const setFalse = () => setValue(false);

  return { value, toggle, setTrue, setFalse };
}
// Використання
import { useToggle } from "./hooks/useToggle";

function Modal() {
  const { value: isOpen,
          toggle,
          setFalse: close } =
    useToggle(false);

  return (
    <>
      <button onClick={toggle}>
        Open
      </button>
      {isOpen && <Dialog onClose={close} />}
    </>
  );
}

Custom Hook — useDebounce

// hooks/useDebounce.ts
import { useState, useEffect } from "react";

export function useDebounce<T>(
  value: T,
  delay: number
): T {
  const [debounced, setDebounced] =
    useState<T>(value);

  useEffect(() => {
    const timer = setTimeout(() => {
      setDebounced(value);
    }, delay);

    // cleanup: скидає таймер
    // при кожній зміні value
    return () => clearTimeout(timer);
  }, [value, delay]);

  return debounced;
}
// Використання: пошук з дебаунсом
function SearchInput() {
  const [query, setQuery] =
    useState("");
  const debouncedQuery =
    useDebounce(query, 300);

  useEffect(() => {
    if (debouncedQuery) {
      console.log("Search: ", debouncedQuery);
      // тут буде API-виклик
      // (детально — Лекція 12)
    }
  }, [debouncedQuery]);

  return (
    <input
      value={query}
      onChange={(e) =>
        setQuery(e.target.value)}
      placeholder="Search..."
    />
  );
}

useDebounce — класичний Custom Hook: state + effect + cleanup. Значення оновлюється лише після delay мс тиші. Cleanup скидає таймер при кожній зміні value.

Custom Hook — useLocalStorage

import { useState, useEffect } from "react";

export function useLocalStorage<T>(
  key: string,
  initial: T
) {
  const [value, setValue] = useState<T>(() => {
    const stored = localStorage.getItem(key);
    return stored ? JSON.parse(stored) : initial;
  });

  useEffect(() => {
    localStorage.setItem(key, JSON.stringify(value));
  }, [key, value]);

  return [value, setValue] as const;
}
// Використання
function Settings() {
  const [theme, setTheme] =
    useLocalStorage("theme", "light");
  const [lang, setLang] =
    useLocalStorage("lang", "uk");

  return (
    <div>
      <select value={theme}
        onChange={(e) =>
          setTheme(e.target.value)}>
        <option>light</option>
        <option>dark</option>
      </select>
    </div>
  );
}

Підсумок

  • Стан живе якомога нижче. Піднімай лише коли потрібно ділитися.
  • useState — локальний простий стан, useReducer — складніша логіка оновлення. useContext — передавання даних через дерево, TanStack Query — server state.
  • Props drilling — антипатерн. Рішення: Context, композиція, стейт-менеджер.
  • Derived state — обчислюй під час рендеру, не зберігай в state.
  • useEffect — для синхронізації з тим, що знаходиться поза React, коли ця синхронізація потрібна через render. Для реакції на клік чи submit зазвичай використовуй event handler.
  • Завжди роби cleanup в useEffect для підписок і таймерів.
  • Custom Hooks — винесення повторно використовуваної stateful-логіки (аналог Vue Composables).
  • eslint-plugin-react-hooks — обов'язковий інструмент.
